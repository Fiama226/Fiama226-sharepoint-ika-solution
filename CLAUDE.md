## Big-picture architecture

AGENTS.md holds the rules; this section is the cross-file wiring you need to be productive quickly.

**Data-flow contract (don't break it):** Routes in `app/*/page.tsx` are synchronous Server Components that call helpers in [lib/data.ts](lib/data.ts), then pass the results as **props** to `components/intranet/*`. Those components **never** import `data/` directly. This is what keeps each component 1:1 with a future SPFx Web Part — props must stay plain-serializable (no callbacks, no implicit React context).

**`Scope` is the keystone:** `Scope = 'global' | DepartementSlug` (see [types/intranet.ts](types/intranet.ts)). Every helper in `lib/data.ts` filters by it. The home page passes `'global'`; each department page ([app/comptabilite/page.tsx](app/comptabilite/page.tsx), etc.) passes its slug. Add content by writing to the relevant `data/*.ts` with the right `scope` — no other wiring needed.

**Real helper names (the docs drift):** `getCompany()` · `getDepartements()` · `getDepartement(slug)` · `getQuickLinks(scope)` · `getNews(scope)` · `getDocuments(scope)` · `getTeam(scope)` · `getEvents(scope)`, plus **home-specific** getters (`getHeroSlides`, `getMissions`, `getHeroStats`, `getFeaturedDocs`, `getHomeQuickAccess`, `getHomeEvents`, `getHomeNews`, `getGalleryImages`, `getHomeCollaborators`, `getEmployeeOfMonth`, `getProjects`, `getHomeDepartements`) and `formatDate`/`formatDateShort`. Home data lives separately in [data/home.ts](data/home.ts) with its own `Home*` types in [types/intranet.ts](types/intranet.ts) (kept apart so the home's marketing tone doesn't leak into department pages). Note: [docs/architecture.md](docs/architecture.md) §3 lists older `*ByScope` names that **don't exist** — trust `lib/data.ts`, not that doc.

**Client/server boundary:** Server Components by default; add `"use client"` only for hooks/interactivity. **Exemplar:** [app/comptabilite/page.tsx](app/comptabilite/page.tsx) is a Server Component that imports `lucide-react` (icons render fine in RSC) and embeds client islands — [finance-charts.tsx](components/intranet/finance-charts.tsx) (recharts), [live-clock.tsx](components/intranet/live-clock.tsx), [faq-list.tsx](components/intranet/faq-list.tsx). **`app/page.tsx` (home) and `app/commerciaux/page.tsx` are themselves client** (sliders/clocks via `useState`/`useEffect`); [site-header.tsx](components/layout/site-header.tsx) is client for `usePathname` + dropdowns. `lib/data.ts` has no `server-only` guard, so client components import it freely. **But its nav has outgrown the "5-route hub" description:** PRIMARY_NAV (5 dept routes) + SECONDARY_NAV (`/organigramme` `/agenda` `/histoire`) + a QUICK_ACCESS dropdown (`/services` `/projects` `/blog`). Most non-primary targets are **dead links** — only home + the 4 dept routes + `/organigramme` + `/histoire` resolve; `/agenda` `/services` `/projects` `/blog` `/profile` `/settings` 404 (the `[Bordereaudesprix]` route exists but isn't linked from the header). Its profile chip also hardcodes `Landry` (`landry@ikasolution.com`, avatar `/assets/team/landry.jpeg`); the `getCompany()` call there is now vestigial (`currentUser` is `Awa Kaboré`, unused). Gotcha: `useState`/`onClick` without `"use client"` breaks the build.

**Icons:** `lucide-react` is the standard — import named icons directly (see the comptabilite page, `site-header.tsx`, `finance-charts.tsx`, `faq-list.tsx`). The legacy inline-SVG `<Icon name="…"/>` registry in [components/intranet/icon.tsx](components/intranet/icon.tsx) still backs older components (quick-links, documents-list) and the SPFx-compatibility path; `name` is a loose `string` so a typo renders `null` silently. Use lucide for new work; only extend the registry to match an existing `<Icon>` usage. [components/layout/site-footer.tsx](components/layout/site-footer.tsx) is the lone `react-icons` consumer (`fa6` brand glyphs for social links, added where lucide lacks brand icons); keep `react-icons` scoped there and use lucide everywhere else.

**Styling & import alias:** Tailwind v4 tokens come from `@theme inline` in [app/globals.css](app/globals.css) — use `bg-brand-navy` / `text-brand-cyan` / `text-brand-muted` etc., never raw hex in JSX. Path alias `@/*` → repo root (tsconfig), so prefer `@/...` imports for anything non-Next.

## Current state & gotchas

- **The home page is mid-flight, not the exemplar.** [app/page.tsx](app/page.tsx) is a client component using inline `style={{…}}` objects, raw hex (`#1355e2`, `#e63946`), `<img>` (not `next/image`), and sports-themed dummy copy ("Champions…", "équipe"). It departs from every convention the department pages follow — use [app/comptabilite/page.tsx](app/comptabilite/page.tsx) as the architecture reference. Don't silently rewrite the home page: it's being redesigned, so confirm scope first.
- **`app/page to come back .tsx` is a stale backup** of `page.tsx` (identical imports). Its filename has spaces and isn't `page.tsx`, so Next.js never routes it and nothing imports it. Edit `app/page.tsx` instead; this file is a deletion candidate.
- **A filename with a space is load-bearing:** [components/intranet/last_home_page section.tsx](components/intranet/last_home_page section.tsx) is imported by `app/page.tsx` — the import path contains the space, so don't casually rename it without updating the import. New files should use kebab-case (the repo currently mixes kebab / snake_case / PascalCase).
- **Three new routes bypass the architecture contract.** [app/organigramme/page.tsx](app/organigramme/page.tsx), [app/histoire/page.tsx](app/histoire/page.tsx), and [app/Bordereaudesprix/page.tsx](app/Bordereaudesprix/page.tsx) are each `"use client"` pages that keep **data and sub-components inline** — no `lib/data.ts`, no `Scope`, no props from a Server Component. They're a distinct pattern from the department pages, not violations of the data-flow contract; don't force them through `lib/data.ts`. They lean on `<img>` / raw hex (`#e63946`) / `<a href="#">` placeholders rather than `next/image` + Tailwind tokens, matching the home page's mid-flight style. `/Bordereaudesprix` (client Excel export, `xlsx`+`file-saver`) is the only route breaking the lowercase-slug convention — PascalCase but routed, so leave it unless asked.
- **[components/intranet/_refonte-v1/](components/intranet/_refonte-v1/) is an archive, not active code.** It holds the 8 pre-refonte home components (kpi-band, welcome-strip, home-quick-links, home-events, home-documents, home-gallery, department-portals, featured-news) superseded by the current home imports — `firstSection` / `News` / `last_home_page section` / `before_last_home_page_section` in [app/page.tsx](app/page.tsx). Kept for reference during the redesign; don't wire them back up.
- **New runtime deps have landed since AGENTS.md §6.** [package.json](package.json) now also pulls `react-icons` (footer brand glyphs, see the Icons note), `xlsx` + `file-saver` (the `/Bordereaudesprix` Excel export, fully client-side). §6's "no new UI deps without validation" still holds going forward — these are incurred exceptions, not precedent.

## Commands note

Commands live in AGENTS.md §6 (`dev`/`build`/`start`/`lint`). Two things AGENTS.md doesn't say:

- **No test framework** is configured (no jest/vitest). There are no tests and no single-test command; "done" = `npm run lint` passes **then** `npm run build` passes (AGENTS.md §6 requires this gate after every change).
- **`lint` runs ESLint flat config directly** (`eslint`, see [eslint.config.mjs](eslint.config.mjs)) — Next 16 removed the old `next lint` wrapper.
